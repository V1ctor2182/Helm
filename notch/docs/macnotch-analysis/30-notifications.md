# MacNotch — Notifications / 刘海通知弹出模块分析

> 复刻目标文档。基于 `reference/macnotch/notifications.mp4`(15.75s,3456×2234,120fps)抽帧分析。
> 抽帧:`frames/notif/dense/n_001..n_158.jpg`(fps=10,900px 宽)+ `frames/notif/`(8 张稀疏帧)。
> 像素/时间为目测估值,已折算到 **逻辑点(pt)**(16″ MBP 默认缩放,native 3456×2234 → 1728×1117pt,device→pt 系数 0.5;900px 抽帧 → pt 系数 ×1.92)。

---

## 0. 关键结论(TL;DR)

- 这不是 macOS 系统右上角横幅通知,而是 **刘海(notch)自身展开的 HUD 面板**:面板始终**水平居中**贴在屏幕顶部物理刘海处。
- 通知 = 刘海从「待机小药丸」**向下 + 向两侧展开**成一张宽卡片。展开极快(≈0.2s)。
- 本视频里出现的是一条 **「Event Reminder」(Microsoft Teams 团队站会日程提醒)**,停留约 **12 秒**,然后**原地交叉淡化(cross-dissolve)切换成 Media 正在播放面板**(不是收回刘海)。
- 待机态刘海本身是一个 **mini now-playing 药丸**:左侧专辑封面缩略图 + 右侧音频可视化跳动条。
- 面板配色:近黑底(#0A0A0C 微蓝),白标题 + 灰副标题,白色胶囊主按钮。圆角很大(尤其底部两角)。

- 黑底药丸,宽 ≈200pt、高 ≈26–30pt。

## 3. 弹出动画(出现)

帧:`n_009`(纯黑药丸)→ `n_010`(已近全尺寸)→ `n_011`(完全展开稳定)。

- **方向**:药丸**同时向下加高、向左右加宽**,内容由透明淡入。不是单纯下垂窗帘,而是「容器膨胀 + 内容 fade-in」。
- **时长**:`n_009`→`n_011` 约 **2 帧 @10fps ≈ 0.2s**(很快,接近一次弹性 ease-out)。
- **缓动估值**:容器尺寸用 `ease-out`(快进慢出),内容透明度 0→1 同步或略滞后 ~1 帧。
- `n_010` 时右侧主按钮文字尚被裁("Join Microsoft Team…"),`n_011` 才完整("Join Microsoft Teams")→ 印证宽度仍在扩张到末帧。
- 没有观察到明显回弹/过冲(overshoot);若要更「弹」可加 `cubic-bezier(.2,.9,.25,1.2)` 轻微过冲,但素材里偏克制。

> 复刻建议:`transform: scaleY/scaleX` 或 width/height + clip,`transition: ~180ms ease-out`;内容 `opacity 150ms`。

```

## 5. 停留与收起 / 视图切换

- **停留时长**:reminder 从 `n_010`(≈1.0s)到 `n_130`(≈13.0s)≈ **12 秒**可见且不变(计时文字一直 1→12s 递增)。
- **本视频的「收起」其实是切视图**:`n_131` 卡片内容整体淡黑/虚化(原容器尺寸保持)→ `n_132` 新内容(Media)淡入 → `n_134` Media 面板成形。
  - **交叉淡化时长** ≈ `n_130`→`n_134` ≈ **0.3–0.4s**。容器尺寸基本不跳变,仅内容 cross-dissolve(可能伴随高度从 reminder→media 的轻微变化)。
- **真正收回刘海(→ idle 药丸)在本片段未出现**(视频结束时仍停在 Media 面板)。收回动画需另取素材;推断为展开的逆向(内容 fade-out + 容器收缩,~0.2s)。
- **hover 行为**:鼠标在片中游走(`n_040`、`n_126` 光标靠近右侧次按钮区),**未观察到明显的暂停计时 / 展开 / 高亮变化**。是否「hover 暂停自动收起」无法从本片确认 → 见不确定清单。

本视频只含一条真实通知 + 一个 Media 面板,但能看出面板是**多视图/分区**结构(头部左侧标题随视图变化):

### 6.1 Event Reminder(通知)— 见 §4

### 6.2 Media / Now-Playing(`n_134`–`n_158`)
头部左:`Media` + 绿点 `Spotify` 芯片 + 小齿轮图标;头部右:圆形设置图标。
```
┌──────────────────────────────────────────────────────────────┐
│ Media  ● Spotify  ⚙                                      ⊙ │
│ Pick an app          Counting My Blessings              [封面]│
│ Open ...             Seph Schlueter · Counting My Bless.     ↗│
│ [ Music][Spotify]    ▬▬▬▬▬▬▬▬▬▬○──────────                    │
│ [YouTube]      0:00     🔀 ⏮ ⏸ ⏭ 🔁           1:31     [封面] │
└──────────────────────────────────────────────────────────────┘
```
- **左栏**「Pick an app」:Apple Music(粉红 `#FA2D6B`)、Spotify(绿 `#1DB954`)、YouTube(红 `#FF0000`)三个圆角 app 图标。
- **中栏**:曲名 `Counting My Blessings`(白 bold ~17pt)、艺人/曲目副标题(灰)、进度条(已播放白、剩余灰)、起止时间 `0:00 / 1:31`、传输控件(随机/上一首/播放暂停/下一首/循环)。
- **右栏**:正方圆角专辑封面(≈64–72pt),右上角小展开箭头。

> 复刻提示:reminder 与 media 共用同一容器(同宽、同圆角、同近黑底),切换时**保留容器、交叉淡化内容**——这是刘海面板的核心交互范式。消息类/系统类通知未在本片出现,推断沿用同一卡片骨架(图标+标题+正文+时间+可选按钮)。

## 8. 不确定清单 / 需补素材

1. **真正的收回(→ idle 药丸)动画**:本视频以 Media 面板结束,未拍到通知/面板收回刘海的过程(方向、时长、缓动均为推断)。

3. **hover 交互**:鼠标经过时未见暂停/展开/按钮高亮;不能断定「悬停暂停」存在与否。
4. **次级按钮文字**:reminder 卡右下两个暗色次按钮 + 底部小链接文字过小不可辨(推测 `Snooze`/`Dismiss`/`view details`)。
5. **头部左侧分段标签**:`Event Reminder` 右边的小分段控件具体文案(疑似 `All`/`Alerts`)未能辨认。
6. **多条通知堆叠**:本片仅同时显示 1 条,未见堆叠/列表/计数行为;不确定是否支持多条堆叠或队列。
7. **消息类 / 系统类通知样式**:仅有日程提醒(Event Reminder)+ 媒体面板两种,其他通知类型外观与差异未知。
