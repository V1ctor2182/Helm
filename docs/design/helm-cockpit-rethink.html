驾驶舱不该是编辑器,该是 agent 指挥台

你说得对:「文件树 + 预览 + 终端」就是 Cursor,Helm 没有理由做一个更弱的 Cursor。 2026 年行业已经给了答案——Devin Desktop 把编辑器降级成 Agent Command Center (「工程师的活从写代码变成指挥工作」),Google Antigravity 的 Mission Control 让你派发多个并行 agent、只做 diff 审查和合并。驾驶舱 = 你盯着 agent 干活、随时接管的地方,不是你自己敲字的地方。 但只抄「多 agent 看板」会变成更弱的 Devin。Helm 的独家赌注是别人都没有的东西:你的第二大脑——活从你的速记/待办/想法来,agent 带着你的记忆干,成果回你的日记/记忆去。

现在的问题

文件树 + 预览 + 终端 = Cursor 的布局。你在「读文件、自己改」,agent 只是躲在终端里。差异化归零。

行业共识(2026)

Devin Desktop / Antigravity Mission Control / Vibe Kanban:驾驶舱=agent 看板 + diff 审查 + 一键合。编辑器降级成抽屉。

Helm 独家赌注

别人管团队的代码工厂。Helm 是单人的、活会回家的驾驶舱:想法→派活→agent 干→成果回记忆。越用越懂你。

A指挥台 · Command Deck 赌注:广度 — 你派活/盯活/收活,不写代码

编辑器彻底退场(只在「接管」时作为抽屉滑出)。三栏:左=意图队列(你的速记/待办/想法排队等派给 agent)、 中=活跃 run 看板(每条 run 都挂着「来自哪条想法 → 去向哪里」)、右=要你处理(diff 待审、权限请求、agent 的选择题)。 最像 Devin,但每条活都长在你的意图上,不是抽象的 repo 任务。

设计理念 · 指挥台

它是什么

一块「谁在干什么、谁需要我」的作战面板。你的角色从「打字的人」变成「派活、盯活、拍板的人」。编辑器只在你主动接管一条 run 时,作为抽屉滑出——默认根本看不到文件树。

为什么不是 Cursor

VSCursor 一次一个编辑器、一个你在敲。这里同时有 N 条 agent 在跑,你在做的是审 diff、答问题、批权限——单人版的空管塔。

为什么不是 Devin

VSDevin 是团队的代码工厂,活是抽象的工单。这里每条 run 都标着「来自哪条速记/想法 → 去哪」,活从你的第二大脑来、成果回你的记忆去。

代价 / 风险

最贴近行业主流,也最容易被读成「抄 Devin」。差异化全压在「意图队列 + 成果回家」这条大脑动线上——如果这条线做浅了,就真成了更弱的 Devin。

B观测台 · Glass Cockpit 赌注:深度 — 读 agent 的意图和轨迹,不读代码

盯住一条 agent,把它做成一块飞机仪表盘:顶排是读数(用时/token/测试绿红/摸的文件/当前动作), 中间是可读的行动轨迹(读了 X → 定位 Y → 改 3 行 → 跑测试 → 47/47 绿),右侧是 diff 读数。 仪表变红你才「抓方向盘」接管。这是 ORAGE 黑座舱北极星真正落地的样子——你读的是 agent 的心智和轨迹,不是一行行代码。

设计理念 · 观测台

它是什么

一台仪表盘,不是编辑器。中间是 agent 的「可读心智」——它读了什么、诊断出什么、改了什么、测试过没有,一条时间轴讲清楚。文件和终端退成周边仪表。你靠读仪表建立信任,不靠逐行读代码。

为什么不是 Cursor

VSCursor 给你看代码,你得自己读懂 agent 干了啥。这里给你看 agent 的意图和轨迹——「它为什么这么改」比「它改了哪一行」更重要,监督成本低一个数量级。

最忠于北极星

DESIGN.md 的北极星是「黑座舱玻璃罩、静默仪表、掌控感>装饰」。这个方向把它真正落地:界面即仪器,accent 只给「活的当下的」(当前动作那格琥珀火苗)。ORAGE 语汇终于名副其实。

代价 / 风险

一次只深看一条 run,广度弱(要配 A 式的 run 列表做入口)。轨迹的可读性全靠后端把 agent 动作结构化上报——ACP 事件流要够细,否则轨迹变成干巴巴的日志。

C回路 · The Loop 赌注:整合 — agent 长在你的第二大脑里(只有 Helm 能做)

把驾驶舱做成一个闭环的可视化:左=来处(这条 run 被什么喂大——哪条速记、命中了哪几条记忆、翻了哪篇 RAG 文档)、 中=agent 在干、右=去处(成果自动落到哪——今日日记、记忆、PR,回执可纠)。 这是 Cursor 和 Devin 都做不到的:它们不知道你的个人大脑。活从你的想法来、带着你的记忆干、成果回你的知识里——越用越懂你。

设计理念 · 回路

它是什么

把一条 agent run 放进它的上下文血脉里看:左边是喂大它的东西(你的速记、记忆、RAG),右边是它的产出落回哪里(日记/记忆/PR)。驾驶舱不是孤立的执行器,是你第二大脑的执行面。

为什么只有 Helm 能做

VSCursor / Devin 不认识你的个人大脑,它们的 agent 只看得到 repo。Helm 的 agent 看得到你的记忆、速记、日记——这是护城河,别人抄不走,因为他们没有你的大脑。

复利效应

每干完一条活,记忆 +1、日记 +1。下一条活命中更多记忆、绕更少弯路。越用越懂你——这是订阅制 Cursor 给不了的个人复利。

代价 / 风险

最激进、最依赖 Helm 其它系统(记忆/RAG/记录都要够强够准)。如果记忆命中是噪音、回执落点不准,「大脑在环」会变成「大脑添乱」。需要 A 或 B 提供实操的干活界面,C 更像是套在外面的语境层。

我的建议:不是三选一,是分层合一

三个方向不冲突,是同一座驾驶舱的三个视角。最强的组合是:A 做骨架(指挥台=默认落地页,多 run 看板 + 要你处理,解决「不是 Cursor」)、 B 做深看(点开任一条 run = 观测台,读轨迹/仪表/diff,解决「读意图不读代码」)、C 做语境层(每条 run 都带「来处→去处」的大脑血脉,解决「只有 Helm 能做」)。 编辑器/文件树/终端全部降级成接管时才滑出的抽屉——它们还在,但不再是门面。

A · 指挥台(骨架)

默认页。回答「凭什么不是 Cursor」——你在指挥一支 agent 舰队,不是编辑一个文件。风险:最像 Devin。

B · 观测台(深看)

单 run 详情。回答「凭什么信任 agent」——读它的心智轨迹而非代码。最忠 ORAGE 北极星。

C · 回路(护城河)

贯穿 A/B 的语境层。回答「凭什么只有 Helm」——agent 长在你的大脑里,越用越懂你。别人抄不走。
